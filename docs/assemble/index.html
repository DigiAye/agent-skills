assemble

Four models. One answer. They take turns building it, doubting it, breaking it and trimming it, round after round, until there's nothing left to fix.

The builder

Gets it working. Fills gaps and fixes every must-fix from the last turn.

Model 1 · then rotates

The skeptic

Assumes it's wrong somewhere and finds where. Checks every claim against the task.

Model 2 · then rotates

The breaker

Empty inputs, failures, security, cost. Whatever the happy path forgot.

Model 3 · then rotates

The simplifier

Cuts what the task didn't ask for. Smaller, clearer, same result.

Model 4 · then rotates
Install How the rounds work

36 rounds, tightening as it goes

A round is one model's turn. A pass is all four. Each block has fewer passes, because the answer should need less each time.

Everyone plays every role

Roles rotate each pass, so no model only ever builds or only ever criticises. Each turn sees the current answer and the last critique, but never who wrote it.

Role played by each model in each pass

It knows when to stop

  • Every critique tags issues as MUST or NICE.
  • A full pass with no MUSTs and only tiny diffs ends the run early.
  • Or a model can declare it done, and the next one has to agree.
  • Stuck for a whole block? It stops and tells you what's blocking.
  • At 36 it always asks before going further.

Where the four come from

In-tool subagents

If your tool can pick a model per subagent. Cursor can mix vendors; in Claude Code and Kiro you get four Claude variants.

Vendor CLIs

claude, codex, gemini and agent, one call per turn. The real multi-vendor team.

Solo mode

One model plays all four roles with a fresh start each turn. Works anywhere.

The CLI mode sends your task to every vendor on the list. Set allowedModels or localOnly in the config to control that.
